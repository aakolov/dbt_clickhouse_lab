# План: Анализ и улучшение проекта dbt_clickhouse_lab

## Текущее состояние проекта

Проект представляет собой реализацию методологии Data Vault 2.0 для хранения данных TPC-H в ClickHouse с использованием dbt.

### Описание назначения проекта

Проект dbt_clickhouse_lab предназначен для:

1. **Хранения данных TPC-H** в ClickHouse с использованием методологии Data Vault 2.0
2. **Создания аналитических представлений** (мартов) для анализа заказов и линейных позиций
3. **Обеспечения семантического слоя** для бизнес-аналитики с метриками и измерениями
4. **Генерации справочного календаря** для унификации временных измерений
5. **Интеграции с S3** для загрузки синтетических данных TPC-H

Команда разработки использует русский язык для комментариев, что указывает на русскоязычную команду.

## Детальное описание недостатков

### 1. Критические недостатки

#### 1.1 Отсутствие основных моделей Data Vault

**Проблема**: Марты ссылаются на отсутствующие Data Vault модели (hubs, links, satellites), что делает проект неработоспособным.

**Влияние**: 
- `f_orders_stats.sql` ссылается на `sat_order_details`, `link_order_customer`, `sat_customer_details`, `link_order_lineitem`, `sat_lineitem_details`
- `f_orders_stats_dv.sql` использует те же отсутствующие модели
- `f_lineorder_flat_dv.sql` ссылается на `sat_lineitem_details`, `link_order_lineitem`, `sat_order_details`, `link_order_customer`, `sat_customer_details`, `sat_supplier_details`, `sat_part_details`

**Расположение**: Ожидается в `models/dv/`, но папка не существует

#### 1.2 Отсутствие тестов для стейджинг-слоя

**Проблема**: В стейджинг-слое отсутствуют тесты валидации качества данных.

**Влияние**: 
- Нет проверок уникальности ключей
- Нет тестов на NULL значения в обязательных полях
- Нет проверок соответствия форматов данных

**Расположение**: Ожидается в `tests/staging/`, но папка не существует

#### 1.3 Пустые или незаполненные директории

**Проблема**: Несколько директорий dbt проекта пусты или отсутствуют.

**Влияние**:
- `analysis/` - отсутствует, невозможно выполнять аналитические исследования
- `data/` - содержит только `.gitkeep`, нет данных для сидов
- `snapshots/` - отсутствует, невозможно использовать Snapshotting в dbt

### 2. Низкоприоритетные недостатки

#### 2.1 Отсутствие CI/CD конфигурации

**Проблема**: GitHub Actions workflow (`build.yml`) не настроен для запуска dbt.

**Влияние**:
- Нет автоматического тестирования изменений
- Нет автоматической валидации моделей
- Нет автоматического развертывания

#### 2.2 Неполные YAML-конфигурации

**Проблема**: Файлы semantic layer (metrics.yml, dimensions.yml, semantic_models.yml) существуют, но содержимое недоступно для чтения в бинарном формате.

**Влияние**:
- Неизвестно, насколько полнофункциональна semantic layer
- Отсутствует прозрачность в определении метрик и измерений

#### 2.3 Отсутствие документации

**Проблема**: В проекте отсутствует README.md с инструкциями по запуску и настройке.

**Влияние**:
- Новые разработчики не могут быстро начать работу
- Процесс настройки окружения не документирован

## План по устранению недостатков

### Приоритет 1: Создание основных моделей Data Vault

#### Задача 1.1: Создать hub модели

Создать 4 hub модели в `models/dv/hub/`:

1. **hub_customer.sql** - hub для клиентов
   - Business key: `C_CUSTKEY`
   - Хранение: `CUSTOMER_HK` (хеш от business key)

2. **hub_order.sql** - hub для заказов
   - Business key: `O_ORDERKEY`
   - Хранение: `ORDER_HK` (хеш от business key)

3. **hub_part.sql** - hub для деталей
   - Business key: `P_PARTKEY`
   - Хранение: `PART_HK` (хеш от business key)

4. **hub_supplier.sql** - hub для поставщиков
   - Business key: `S_SUPPKEY`
   - Хранение: `SUPPLIER_HK` (хеш от business key)

#### Задача 1.2: Создать link модели

Создать 2 link модели в `models/dv/link/`:

1. **link_order_customer.sql** - связь "заказ-клиент"
   - Хеш-ключи: `ORDER_HK`, `CUSTOMER_HK`
   - Порядок хранения: по `ORDER_HK`

2. **link_order_lineitem.sql** - связь "заказ-позиция"
   - Хеш-ключи: `ORDER_HK`, `ORDER_LINEITEM_HK`
   - Порядок хранения: по `ORDER_HK`, `ORDER_LINEITEM_HK`

#### Задача 1.3: Создать satellite модели

Создать 5 satellite моделей в `models/dv/sat/`:

1. **sat_order_details.sql** - детали заказа
   - Годовая партиция: `toYear(O_ORDERDATE)`
   - Порядок: `ORDER_HK`, `LOAD_DATE`

2. **sat_customer_details.sql** - детали клиента
   - Хранение: `CUSTOMER_HK` порядок

3. **sat_lineitem_details.sql** - детали позиции
   - Годовая партиция: `toYear(L_SHIPDATE)`
   - Порядок: `ORDER_LINEITEM_HK`, `LOAD_DATE`

4. **sat_part_details.sql** - детали детали
   - Хранение: `PART_HK` порядок

5. **sat_supplier_details.sql** - детали поставщика
   - Хранение: `SUPPLIER_HK` порядок

### Приоритет 2: Создание тестов

#### Задача 2.1: Тесты для стейджинг-слоя

Создать тесты в `tests/staging/`:

1. **test_stg_customer_uniqueness.sql** - проверка уникальности `C_CUSTKEY`
2. **test_stg_orders_uniqueness.sql** - проверка уникальности `O_ORDERKEY`
3. **test_stg_lineitem_uniqueness.sql** - проверка уникальности `L_ITEMKEY`
4. **test_stg_part_uniqueness.sql** - проверка уникальности `P_PARTKEY`
5. **test_stg_supplier_uniqueness.sql** - проверка уникальности `S_SUPPKEY`
6. **test_stg_no_null_keys.sql** - проверка отсутствия NULL в ключевых полях

#### Задача 2.2: Тесты для Data Vault моделей

Создать тесты в `tests/dv/`:

1. **test_hub_uniqueness.sql** - проверка уникальности хеш-ключей в hubs
2. **test_link_integrity.sql** - проверка ссылочной целостности links
3. **test_sat_load_date_consistency.sql** - проверка последовательности LOAD_DATE
4. **test_sat_hashdiff.sql** - проверка корректности hashdiff

### Приоритет 3: Подготовка проекта

#### Задача 3.1: Создать недостающие директории

```bash
mkdir analysis data snapshots tests/staging tests/dv models/dv/hub models/dv/link models/dv/sat
```

#### Задача 3.2: Создать README.md

Создать README.md с:
- Описанием проекта
- Инструкциями по запуску
- Описанием архитектуры

#### Задача 3.3: Настроить CI/CD

Обновить `.github/workflows/build.yml` для:

## Заключение

Проект dbt_clickhouse_lab имеет четкое архитектурное решение на основе Data Vault 2.0 и семантического слоя, но требует заполнения критически важных отсутствующих моделей и тестов. Основной фокус улучшения - создание Data Vault моделей, так как марты уже существуют и могут быть использованы как спецификация для satellite и link моделей.
